## מה `fetch` לא עושה

| מה שנדמה            | מה שבאמת                                                   |
| ------------------- | ---------------------------------------------------------- |
| זורק על 404 ועל 500 | **לא.** ההבטחה מתקיימת, ו-`res.ok` הוא `false`             |
| יש לו פסק זמן       | **אין.** ומעולם לא היה. בקשה יכולה להיתקע לנצח             |
| התשובה היא הנתונים  | **לא.** `res.json()` הוא `await` שני ודבר שני שיכול להיכשל |
| `try/catch` מכסה    | רק את המקרה שבו **הבקשה לא הושלמה**. זה אחד מתוך חמישה     |

**`fetch` נדחה במקרה אחד בלבד: הבקשה לא הושלמה.** DNS, אין נתיב, CORS, ביטול. זהו.

```js
const res = await fetch(url, { signal });
if (!res.ok) throw new ApiError('status', '...', `HTTP ${res.status}`);
let data;
try {
  data = await res.json();
} catch {
  throw new ApiError('shape', '...', '...');
}
return normalise(data);
```

## חמשת המצבים

`#api-panel` נושא `data-state`, ותמיד **בדיוק אחד** מהם:

| המצב      | מתי                   | ומה זה **לא**                            |
| --------- | --------------------- | ---------------------------------------- |
| `idle`    | עוד לא חיפשו כלום     | לא `empty`. אף אחד לא שאל                |
| `loading` | בקשה פתוחה            | ולא **אחרי** ה-await — שם זה כבר לא נכון |
| `error`   | נכשלה, ויש משפט       | משפט **וגם דרך קדימה**, לא "משהו השתבש"  |
| `empty`   | הצליחה, ולא מצאה כלום | לא שגיאה. השרת ענה, והתשובה היא "אין"    |
| `results` | הצליחה, ומצאה         |                                          |

**שדה אחד עם חמישה ערכים, לא חמישה בוליאנים.** חמישה בוליאנים הם 32 צירופים שרק חמישה
מהם אומרים משהו — ואת השאר מייצר `isEmpty = false` אחד ששכחו.

```js
if (status === 'loading') return 'loading';
if (status === 'error') return 'error';
if (status === 'idle') return 'idle';
return results.length === 0 ? 'empty' : 'results';
```

**`empty` נגזר. `loading` נשמר.** "האם חזר משהו" היא שאלה על `results`. "האם יש בקשה
פתוחה" לא נגזרת משום דבר.

## תיבת החיפוש — ארבע שורות

```js
let controller = null;
let seq = 0;

async function run(query) {
  controller?.abort(); // 1 — the previous one is not wanted
  controller = new AbortController();
  const ticket = ++seq; // 2 — a ticket per search

  setState({ status: 'loading', error: null }); // 3 — BEFORE the await

  const results = await search(query, { signal: controller.signal });

  if (ticket !== seq) return; // 4 — a newer search has started
  setState({ status: 'done', results });
}
```

| השורה            | מה היא עוצרת  | ולמה שתיהן                                                 |
| ---------------- | ------------- | ---------------------------------------------------------- |
| `abort()`        | את **הרשת**   | הבקשה נגמרת ולא ממשיכה לרוץ                                |
| `ticket !== seq` | את **הכתיבה** | תשובה שכבר הגיעה לפני שהביטול נחת עדיין מריצה את ההמשך שלה |

ולפני שתי אלה — **השהיה**: `clearTimeout` ואז `setTimeout(..., 300)`. מילה בת שש
אותיות היא בקשה אחת ולא שש.

**`AbortError` הוא לא שגיאה:**

```js
if (error.name === 'AbortError') return;
```

**לפי שם ולא לפי מחלקה** — `TimeoutError` הוא גם `DOMException`, והוא כן שגיאה.

## CORS בשלוש שורות

**הבקשה יצאה. השרת ענה. הדפדפן סירב למסור לך את התשובה**, כי היא לא נשאה כותרת שאומרת
שמותר לך לקרוא אותה.

לכן השגיאה היא `TypeError: Failed to fetch` בלי שום פרט — **אותו אובייקט בדיוק** שכבל
מנותק מייצר. הסיבה מודפסת בקונסולה על ידי הדפדפן, ואי אפשר לקרוא אותה מ-JavaScript.

| אפשר                          | אי אפשר                                      |
| ----------------------------- | -------------------------------------------- |
| לבחור API ששולח את הכותרת     | כל דבר ב-JavaScript שלך                      |
| שרת משלך באמצע (אין לו דפדפן) | `mode: 'no-cors'` — נותן תשובה אטומה בלי גוף |
| לבקש מבעל ה-API להוסיף        | תוסף שמכבה את הבדיקה — מתקן רק את הלפטופ שלך |
|                               | `try/catch` — תופס את השגיאה, לא מביא נתונים |

## שבע הטעויות של השבוע

1. **שכחת `await`.** `items.length` הוא `undefined`, כי `items` הוא Promise.
2. **`await` בתוך לולאה** לחמש בקשות שאינן תלויות זו בזו. פי חמישה זמן, בחינם.
3. **הנחת ש-`fetch` זורק על 404.** הוא לא. `res.ok` הוא הבדיקה.
4. **אין מצב שגיאה בממשק.** המשתמש רואה מסך שלא זז ולא יודע למה.
5. **בקשה בכל הקשה.** שש אותיות, שש בקשות, וחמש מהן איש לא רצה.
6. **דחייה שאיש לא תפס.** `unhandledrejection` בקונסולה, ומסך שלא מגיב.
7. **"CORS זה באג בקוד שלי."** לא. זה הדפדפן, והוא עושה את זה בכוונה.
