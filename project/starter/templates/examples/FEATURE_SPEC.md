# מפרט פיצ'ר — סינון, סגנון ומיון של המדף

| | |
|---|---|
| **הקובץ** | `project/specs/filter-and-sort.md` |
| **שבוע** | 9 |
| **סטטוס** | נבדק |

## 1. מה המשתמש יכול לעשות אחרי זה, ולא יכול לפניו

המשתמש יכול לצמצם מדף של ארבעים אלבומים לשלושה שהוא מחפש — לפי טקסט, לפי סגנון,
ובסדר שהוא בוחר.

## 2. מה משתנה ב-state

```js
// לפני
{ shelf: [...], search: {...} }

// אחרי
{ shelf: [...], query: '', genre: 'all', sort: 'added-desc', search: {...} }
```

**שדות חדשים:** `query` (`string`, `''`) · `genre` (`string`, `'all'`) ·
`sort` (`SortKey`, `'added-desc'`).

**מה במפורש לא נוסף:** `visibleShelf`. הרשימה המסוננת **נגזרת** ב-
`selectVisible(state)` ולא נשמרת. אם היא הייתה נשמרת, כל מקום שמשנה את
`shelf` — הוספה, הסרה, דירוג, ביטול — היה צריך לזכור לחשב אותה מחדש, וזה
בדיוק המקום שבו אחד מהם יישכח. מה שיישכח יהיה גלוי על המסך.

## 3. מה משתנה על המסך

| האזור | מה נוסף / משתנה |
|---|---|
| סרגל כלים חדש מעל המדף | שדה חיפוש, `<select>` לסגנון, `<select>` למיון. **סימון סטטי** — לא מרונדר |
| `#shelf-count` | "N מתוך M אלבומים על המדף". אחרי סינון שני המספרים שונים, וזה כל הרעיון |
| `#shelf` | מציג את `selectVisible(state)` במקום את `state.shelf` |
| `#shelf-genre` | ה-`<option>`-ים נגזרים מהמדף. אלבום ג'אז ראשון מוסיף אפשרות; הסרת האחרון מסירה אותה |

**מצב ריק שלישי:** יש אלבומים והסינון מסתיר את כולם. זה לא "המדף ריק" ולא
"החיפוש לא מצא" — ההודעה אומרת כמה יש בסך הכול ומציעה כפתור שמנקה את הסינון,
כי הפקדים של המשתמש הם הסיבה וכדאי לומר לו את זה.

## 4. האירועים

| האירוע | על איזה אלמנט מקשיבים | מה ההנדלר עושה |
|---|---|---|
| `input` | `#shelf-query` | `setState({ query: el.value })` |
| `change` | `document` (האצלה) | `#shelf-genre` → `setState({ genre })`; `#shelf-sort` → `setState({ sort })` |
| `click` | `document` (האצלה) | `[data-action="clear-filters"]` → מאפס את שניהם |

שלוש החלטות:

- **`input` ולא `change` על שדה הסינון.** סינון תוך הקלדה הוא עזרה: כל תו
  מראה יותר ממה שרצית. (ולידציה תוך הקלדה היא נדנוד — זה ההבדל, וטופס
  החיפוש בקטלוג באמת מוודא רק ב-submit.)
- **הסרגל הוא סימון סטטי.** הוא מכיל שדה טקסט, ורינדור מחדש בכל תו היה מוחק
  את השדה מתחת לסמן.
- **`<select>` דווקא כן מרונדר**, כי האפשרויות שלו נגזרות. זה בטוח: האלמנט
  עצמו לא מוחלף, רק הילדים שלו, ולכן הפוקוס שורד. מחליפים ילדים של פקד
  ממוקד — בסדר. מחליפים את הפקד — לא.

## 5. מקרי קצה

| המקרה | ההתנהגות הנכונה |
|---|---|
| הסינון הוא רווחים בלבד | `trim()` — נחשב ריק, כל המדף מוצג |
| סינון שלא תואם לאף אלבום | המצב הריק השלישי, עם כפתור ניקוי |
| הסגנון שנבחר שייך לאלבום שהוסר בזמן שהוא מסונן | הסגנון נעלם מהאפשרויות; הסינון חוזר ל-`all` ולא נשאר על ערך שלא קיים |
| מיון לפי שנה כשלאלבום אין שנה | `null` ממוין אחרון בשני הכיוונים. לא כשנת 0 |
| מיון לפי דירוג ולשניים אותו דירוג | שובר שוויון לפי שם, אחרת הסדר קופץ בין רינדורים |
| שמות בעברית ובאנגלית מעורבבים | `localeCompare(…, 'he')`, לא `<` |
| המדף ריק לגמרי | הסרגל מוצג אבל לא עושה כלום. המצב הריק הוא "אין עדיין אלבומים" |
| 200 אלבומים | סינון על 200 פריטים בכל תו הוא מיקרו-שנייה. אין `debounce` ואין צורך בו |

## 7. הביקורת — נמלא **אחרי** שהקוד קיים

**מה ביקשתי בפועל:** רשומה 3 ב-`PROMPTS.md`.

**מה חזר, בשורה אחת:** `selectVisible` נכונה, שלושת ההנדלרים נכונים, וסרגל
הכלים שהוא כתב מרונדר בתוך `renderShelf`.

**מה היה שגוי או מיותר, ואיך תיקנתי:**

| מה מצאתי | למה זה שגוי | מה עשיתי |
|---|---|---|
| הסרגל, כולל שדה הטקסט, נבנה בתוך `renderShelf` | כל תו מפעיל `setState` שמרנדר מחדש ומוחק את השדה. בפועל: אפשר להקליד תו אחד ואז הפוקוס נעלם | העברתי את הסרגל לסימון סטטי ב-`index.html` |
| `debounce` של 300ms על ההקלדה | מוצדק מול רשת, כאן זה `.filter` על מערך בזיכרון. עיכוב מורגש בתמורה לכלום | הסרתי |
| `state.filteredShelf`, מעודכן בכל הנדלר | שני מקורות אמת. ההנדלר של הדירוג לא עדכן אותו, ולכן דירוג בזמן סינון החזיר את הרשימה הלא-מסוננת | מחקתי את השדה. `selectVisible` נגזרת |
| מיון בעברית עם `a.title > b.title` | סדר לפי קוד תו, לא סדר אלפביתי בעברית | `localeCompare(…, 'he')` בכל חמשת המשוואות |
| `year` חסר טופל כ-`0` | ממיין אלבום בלי תאריך לפני 1955 | `?? -Infinity`, אחרון בשני הכיוונים |

חמישה דברים. **שלושה מהם עבדו מושלם בהדגמה** — הרשימה הכפולה נשברת רק כשמדרגים
בזמן שהסינון פעיל, וה-`localeCompare` נשבר רק כשיש שם בעברית. זה מה שהופך את
סעיף 5 לחלק החשוב במסמך: מקרה קצה שלא כתוב במפרט לא נבדק, ומה שלא נבדק עובד עד
שמישהו אחר משתמש בזה.

**מה קיבלתי כמו שהוא, ואני יכול להסביר כל שורה בו:** מבנה `COMPARATORS` —
אובייקט שממפה מפתח מיון לפונקציית השוואה, במקום `switch` בן חמישה מקרים. אני
מבין למה זה עובד (`COMPARATORS[state.sort]` מחזיר פונקציה, ו-`.sort` מקבל
פונקציה) ולמה זה טוב יותר: להוסיף מיון שישי זו שורה אחת באובייקט, ואם המפתח
שגוי הקוד נופל מיד במקום להחליק לענף ברירת מחדל שקט.
