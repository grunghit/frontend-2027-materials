# יומן פרומפטים — Record Shelf

## 4. מודול הטיפוסים ושני השומרים

| | |
|---|---|
| **תאריך** | שבוע 12 |
| **הכלי** | Claude Code |
| **המפרט** | `project/specs/types-module.md` |

**מה ביקשתי:**

```
בהתאם ל-project/specs/types-module.md, צור ts/types.ts שמכיל את הטיפוסים
של Album, ShelfEntry, AppState ו-LoadState, וכן שני type guards בזמן ריצה:
isAlbum ו-isShelfEntry.

אילוצים:
- אין תלויות. אין ספריית ולידציה.
- הקובץ נבדק גם ב-`tsc --noEmit` בלי tsconfig, כלומר עם lib ברירת המחדל (ES5).
  לכן אסור להשתמש ב-Array.prototype.includes, ב-Object.entries או ב-startsWith.
- isAlbum חייב לדחות אובייקט בלי id או בלי title, ולקבל אובייקט שחסרים בו
  year, trackCount או artwork (הם null-able).
- אל תיגע בשום קובץ אחר.
```

**מה חזר:** הטיפוסים נכונים, שני השומרים נכונים בשלד, ו-`isShelfEntry` בדק את
`rating` מול איחוד הליטרלים.

**מה היה לא בסדר:** `if (!([0,1,2,3,4,5] as const).includes(value.rating))` —
גם `includes` שאסרתי במפורש, וגם השוואה מול טיפוס בזמן ריצה. `Rating` הוא
איחוד ליטרלים, כלומר רעיון של זמן קומפילציה; ברגע שהקוד רץ, מה שיש שם הוא
מספר שיצא מ-`localStorage` של מישהו.

**מה עשיתי:** החלפתי בבדיקה של מספר שלם בטווח:
`typeof rating !== 'number' || rating % 1 !== 0 || rating < 0 || rating > 5`.
הוספתי הערה בקובץ שמסבירה למה, כי זו טעות שקל לחזור אליה.

**מה למדתי על הפרומפט עצמו:** אילוץ שנוסח כאיסור ("אסור `includes`") נשמר
פחות טוב מאילוץ שנוסח כסיבה. כשהוספתי *למה* — "כי הקובץ נבדק עם lib של ES5" —
הוא הפסיק להציע שיטות ES2015 גם בפרומפטים הבאים. הוא גם, לראשונה, ציין בעצמו
שהוא ויתר על גישה מסוימת בגלל האילוץ, מה שנתן לי מה לבדוק.

## 3. סינון ומיון של המדף

| | |
|---|---|
| **תאריך** | שבוע 9 |
| **הכלי** | Claude Code |
| **המפרט** | `project/specs/filter-and-sort.md` |

**מה ביקשתי:**

```
יישם את project/specs/filter-and-sort.md.
```

**מה חזר:** `selectVisible` נכונה, שלושה הנדלרים נכונים, שדה `filteredShelf`
ב-state שלא ביקשתי, סרגל כלים מרונדר בתוך `renderShelf`, ו-`debounce`.

**מה היה לא בסדר:** חמישה דברים, מפורטים בסעיף 7 של המפרט. השניים המהותיים:
מקור אמת כפול (`filteredShelf` לצד `shelf`), ושדה טקסט בתוך אזור מרונדר — מה
שאומר שאפשר להקליד תו אחד ואז הפוקוס נעלם.

**מה עשיתי:** מחקתי את `filteredShelf`, העברתי את הסרגל לסימון סטטי, הסרתי את
ה-`debounce`, ותיקנתי מיון בעברית ואת הטיפול ב-`year` חסר.

**מה למדתי על הפרומפט עצמו:** "יישם את המפרט" בלי לחזור על האילוצים לא עובד,
גם כשהאילוצים כתובים במפרט. **מה שעזר בפועל: לצטט את חוק הארכיטקטורה בגוף
הפרומפט** — "ההנדלר משנה state וקורא ל-render, הוא לא מצייר בעצמו", ו"כל מה
שאפשר לגזור אינו נשמר ב-state". מאז שאני מדביק את שתי השורות האלה, `filteredShelf`
לא חזר.

## 2. שכבת ה-API

| | |
|---|---|
| **תאריך** | שבוע 11 |
| **הכלי** | Claude בדפדפן (מסלול ללא מנוי) |
| **המפרט** | `project/specs/catalogue-search.md` |

**מה ביקשתי:**

```
כתוב js/api.js עם פונקציה searchCatalogue(term) שקוראת ל-iTunes Search API
ומחזירה מערך של Album מנורמל. דרישות: בדיקת res.ok, פסק זמן עם AbortController,
ניסיון חוזר אחד בלבד על כשל רשת, ושגיאה שנושאת משפט בעברית למשתמש.
```

**מה היה לא בסדר:** שני דברים, ואחד מהם היה מסוכן.

הראשון: `catch` יחיד שהחזיר `[]` בכל כשל. כלומר תקלת רשת הוצגה למשתמש כ"לא
נמצאו אלבומים". זו לא אי-דיוק — זה משקר למשתמש על מה שקרה, ושולח אותו לתקן את
האיות במקום את החיבור. מצב ריק ומצב שגיאה הם שני דברים.

השני: הוא ניסה מחדש גם על 404 ועל 500. ניסיון חוזר על 404 הוא 404 פעמיים.

**מה עשיתי:** הפרדתי — `!res.ok` זורק ויוצא מהלולאה מיד; רק כשל רשת ופסק זמן
נכנסים לניסיון החוזר. הוספתי `ApiError` עם `messageHe` נפרד מהפרטים
הטכניים, כדי ש"TypeError: Failed to fetch" לא יגיע למסך.

**מה למדתי על הפרומפט עצמו:** ביקשתי "טיפול בשגיאות" וקיבלתי `catch` שמחזיר
מערך ריק — שזה טכנית טיפול. הניסוח שעובד הוא **מה המשתמש צריך לראות בכל מצב**,
לא "טפל בשגיאות". מאז אני מדביק את טבלת ארבעת המצבים מהמפרט לתוך הפרומפט
עצמו, וזה שינה את התשובות יותר מכל דבר אחר שניסיתי.

## 1. בלוק ה-`@theme` המשותף לשלושה עמודים

| | |
|---|---|
| **תאריך** | שבוע 7 |
| **הכלי** | Claude בדפדפן |
| **המפרט** | אין — שאלת הבנה |

**מה ביקשתי:**

```
בלי שלב בנייה, עם Tailwind v4 מ-build של דפדפן, איך אני חולק בלוק @theme אחד
בין שלושה קבצי HTML במקום להעתיק אותו שלוש פעמים?
```

**מה חזר:** להוציא לקובץ `theme.css` ולטעון אותו עם
`<link rel="stylesheet" href="theme.css" type="text/tailwindcss">`.

**מה היה לא בסדר:** זה לא עובד, וזה נכשל **בשקט**. העמוד נטען, `p-6` עבד,
וכל utility שנשען על טוקן משלי חזר לברירת מחדל — כלומר `text-brand` יצא שחור.
אפס שגיאות בקונסול. זה נראה בדיוק כמו עמוד שלא כתבתי בו מחלקות.

**מה עשיתי:** בדקתי בעצמי שלוש דרכים במקום להאמין לתשובה.

| מה ניסיתי | מה קרה |
|---|---|
| `<link … type="text/tailwindcss">` | מתעלמים בשקט. הטוקנים לא הגיעו |
| `@import "theme.css"` בתוך בלוק `<style type="text/tailwindcss">` | נדחה במפורש: *"The browser build does not support @import"* |
| קובץ JS שמזריק `<style type="text/tailwindcss">` לפני שהסקריפט של Tailwind רץ | **עובד.** מדדתי: `--spacing: 0.5rem` בקובץ המשותף שינה את `p-6` מ-24px ל-48px |

הדרך השלישית היא `js/theme.js`, והתיעוד של שתי הקודמות נמצא בראש הקובץ — כדי
שאף אחד לא ינסה אותן שוב.

**מה למדתי על הפרומפט עצמו:** על שאלה מהצורה "האם X נתמך" התשובה תמיד תישמע
בטוחה, כי צורת התשובה זהה בין ידיעה לניחוש. מאז, על כל שאלת יכולת, אני מבקש
**איך לבדוק** לפני שאני מבקש מה נכון — ובודק. שתי דקות של בדיקה חסכו כאן עמוד
שנראה שבור בלי שום הודעה שאומרת למה.
