## 1. התקנת VS Code

זה העורך היחיד שנשתמש בו בקורס. לא כי אחרים גרועים — אלא כי כל ההגדרות, התוספים והמדריכים
כאן בנויים עליו, ואין מתרגל שיתאים אותם לעורך אחר.

### מסלול macOS

1. גש אל `https://code.visualstudio.com` ולחץ על כפתור ההורדה. האתר מזהה לבד שאתה על מק.
2. פתח את קובץ ה-ZIP שירד. תקבל אפליקציה בשם `Visual Studio Code`.
3. **גרור אותה לתיקיית `Applications`.** אם תפעיל אותה מתיקיית ההורדות, חלק מהדברים יעבדו
   מוזר בהמשך.
4. הפעל אותה. אם מוצגת אזהרה שהאפליקציה הורדה מהאינטרנט — אשר.
5. **חשוב:** פתח את לוח הפקודות ב-`Cmd+Shift+P`, הקלד `shell command`, ובחר
   `Shell Command: Install 'code' command in PATH`.
   בלי זה לא תוכל לפתוח תיקייה מהטרמינל, וזה יחזור אליך בפרק 6.

### מסלול Windows

1. גש אל `https://code.visualstudio.com` ולחץ על כפתור ההורדה. הורד את גרסת ה-**User Installer**
   (64-bit) — היא לא דורשת הרשאות מנהל.
2. הפעל את קובץ ההתקנה.
3. במסך `Select Additional Tasks` **סמן את שתי התיבות האלה**:
   - `Add "Open with Code" action to Windows Explorer file context menu`
   - `Add to PATH (requires shell restart)`
   השנייה היא החשובה. בלעדיה תקבל בהמשך `'code' is not recognized`.
4. סיים את ההתקנה והפעל את VS Code.

## 2. התוספים — ומה כל אחד עושה

**אינך צריך לחפש אותם.** בכל תיקייה שתקבל בקורס יש קובץ `.vscode/extensions.json`, ובפעם
הראשונה שתפתח את התיקייה VS Code יציג בפינה הודעה: *"This workspace has extension
recommendations"*. לחץ **Install All**.

אם ההודעה לא הופיעה: פתח את לוח התוספים (`Cmd+Shift+X` במק, `Ctrl+Shift+X` בחלונות), הקלד
בשורת החיפוש `@recommended`, ולחץ על כפתור ההתקנה ליד הקבוצה.

| התוסף | בשביל מה הוא |
|---|---|
| **Live Server** | מריץ את העמוד דרך שרת אמיתי. זה הכלל של הקורס, ופרק 3 מסביר למה |
| **Prettier** | מסדר את הקוד בכל שמירה. אתה לא מפסיד נקודות על הזחה, וההבדלים בקומיטים נשארים קריאים |
| **ESLint** | תופס את טעויות ה-JavaScript האמיתיות — משתנה שלא בשימוש, `==` במקום `===` — לפני הדפדפן |
| **Tailwind CSS IntelliSense** | משבוע 6: השלמה אוטומטית ותצוגה מקדימה למחלקות של Tailwind |
| **Error Lens** | מציג את השגיאה **על השורה עצמה**, לא מוחבאת בפאנל. בקורס בלי מתרגל, זה התוסף הכי שימושי כאן |
| **HTMLHint** | ולידציה של HTML תוך כדי הקלדה — אותן בדיקות שנריץ בשבוע 1 |
| **GitLens** | מראה מי שינה כל שורה ומתי. הופך את "מה שיניתי ומתי" למשהו שרואים |
| **Path Intellisense** | משלים נתיבים יחסיים. הבאג הכי נפוץ בשבוע 1 הוא `src` או `href` שבור |

התוספים האלה הם לא קישוט. **Error Lens ו-HTMLHint יחסכו לך את רוב הזמן שהיית מבזבז על
שגיאות כתיב בשבועות הראשונים.**

## 3. Live Server — והכלל שלא משתנה

> [!constraints] הכלל הכי חשוב מהשבוע הראשון
> **עמוד נפתח תמיד דרך Live Server. אף פעם לא בלחיצה כפולה על הקובץ.**
> לחיצה כפולה פותחת אותו בכתובת `file://`, וזה שובר את `fetch` (שבוע 11), מודולים של ES
> (שבוע 8) ו-`localStorage` (שבוע 11). ההרגל שנוצר בשבוע 1 מתפוצץ בשבוע 11.

### איך מריצים (זהה בשני המסלולים)

1. פתח ב-VS Code את **התיקייה**, לא קובץ בודד: `File > Open Folder…`
2. לחץ לחיצה ימנית על `index.html` בסייר הקבצים.
3. בחר **`Open with Live Server`**.
4. הדפדפן ייפתח בכתובת `http://127.0.0.1:5500/index.html`.

**הסתכל בשורת הכתובת.** אם כתוב שם `file:///` — סגור את הלשונית ונסה שוב. אם כתוב
`http://127.0.0.1:5500` — אתה בסדר. בשורת הסטטוס הכחולה בתחתית VS Code יופיע גם
הכיתוב `Port : 5500`; לחיצה עליו עוצרת את השרת.

**הפורט 5500 נעול בהגדרות שקיבלת** (`.vscode/settings.json`). אל תשנה אותו. בשבוע 11 נשמור
נתונים בדפדפן, והם שייכים לכתובת המדויקת שבה העמוד רץ — אם הפורט זז, הנתונים "נעלמים".

עדיין לא צריך להבין את המילים `fetch`, `origin` או `localStorage`. תיפגש בהן שוב בשבוע 11,
וההרגל כבר יהיה נכון.

## 4. Node.js — גרסת LTS

Node לא נחוץ לכתיבת HTML, אבל הבדיקות האוטומטיות רצות עליו — גם אצלך במחשב וגם במאגר שלך
בכל דחיפה. **התקן את גרסת ה-LTS**, לא את גרסת ה-Current.

### מסלול macOS

1. גש אל `https://nodejs.org` והורד את החבילה המסומנת **LTS** (קובץ `.pkg`).
2. הפעל את הקובץ ואשר את כל השלבים.
3. **פתח טרמינל חדש** — לא כזה שהיה פתוח מקודם — והרץ:

```bash
node -v
npm -v
```

אתה אמור לראות שתי שורות, כל אחת מתחילה במספר. למשל `v22.11.0` ו-`10.9.0`.

**אם קיבלת `zsh: command not found: node`:** הטרמינל לא יודע איפה Node הותקן. סגור את כל
חלונות הטרמינל ופתח חדש. אם זה לא עזר, ראה תקלה **א-1** בנספח.

### מסלול Windows

1. גש אל `https://nodejs.org` והורד את החבילה המסומנת **LTS** (קובץ `.msi`).
2. הפעל את קובץ ההתקנה ואשר את כל השלבים. **השאר את התיבה `Add to PATH` מסומנת** — היא
   מסומנת כברירת מחדל.
3. במסך `Tools for Native Modules` אין צורך לסמן כלום. אנחנו לא מקמפלים כלום בקורס הזה.
4. **סגור לגמרי את VS Code ופתח אותו מחדש.** זה לא טקס — משתני סביבה נטענים כשהתוכנה עולה,
   וטרמינל שהיה פתוח לפני ההתקנה לא יראה את Node לעולם.
5. פתח טרמינל משולב (``Ctrl+` ``) והרץ:

```bash
node -v
npm -v
```

**אם קיבלת `'node' is not recognized as an internal or external command, operable program or
batch file.`:** ראה תקלה **א-2** בנספח.

## 5. Git

### מסלול macOS

Git כבר קיים על רוב המקים. בדוק:

```bash
git --version
```

אם קיבלת מספר גרסה — אתה מסודר. אם נפתח חלון שמציע להתקין `Command Line Developer Tools`,
אשר והמתן; זה לוקח כמה דקות.

### מסלול Windows

1. גש אל `https://git-scm.com/download/win` וההורדה תתחיל לבד.
2. הפעל את קובץ ההתקנה. **רוב המסכים אפשר לאשר כמו שהם**, חוץ משניים:
   - `Choosing the default editor used by Git` — בחר **`Use Visual Studio Code as Git's default
     editor`**. ברירת המחדל היא Vim, ומי שנקלע לתוכו בטעות מתקשה לצאת.
   - `Adjusting the name of the initial branch` — בחר **`Override the default branch name`**
     והשאר `main`.
3. סיים, סגור את VS Code ופתח מחדש.

```bash
git --version
```

### הגדרות שחייבים לעשות פעם אחת (שני המסלולים)

Git חותם כל קומיט בשם ובמייל שלך. בלי זה הוא פשוט יסרב לעשות קומיט.

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```

השתמש **באותו מייל** שאיתו תפתח את חשבון הגיטהאב, אחרת הקומיטים שלך לא יקושרו לחשבון שלך.

### שורות ומעברי שורה — ההגדרה שאף אחד לא מסביר

**macOS:**

```bash
git config --global core.autocrlf input
```

**Windows:**

```bash
git config --global core.autocrlf true
```

בדוק שהכול נקלט:

```bash
git config --global --list
```

#### ומה `.gitattributes` עושה בשבילך

בכל תיקייה שתקבל בקורס יש קובץ בשם `.gitattributes`, ובו שורה אחת:

```
* text=auto eol=lf
```

הרקע: מק ו-Windows מסמנים סוף שורה אחרת. בלי השורה הזו, קובץ שנערך במק ואז בחלונות נראה
ל-Git כאילו **כל שורה בו השתנתה** — גם אם שינית תו אחד. זה הורס כל אפשרות לקרוא מה השתנה,
ושובר את הבדיקות האוטומטיות שמשוות קבצים.

השורה הזו אומרת ל-Git: אחסן הכול עם סוף שורה אחיד. **אתה לא צריך לעשות איתה כלום** — היא
כבר בתיקייה. רק אל תמחק אותה, ואל תתרגש מהאזהרה
`warning: LF will be replaced by CRLF` בחלונות; היא תקינה (תקלה **א-10**).

## 6. גיטהאב — החשבון, המאגר, וההרשאה שלי

### 6.1 פתיחת חשבון

1. גש אל `https://github.com/signup`.
2. השתמש **באותו מייל** שהגדרת ב-`git config user.email`.
3. בחר שם משתמש שתסכים שיופיע לצידך גם בעוד חמש שנים.
4. אשר את המייל.

**חשבון אישי חינמי. אין צורך בארגון, אין צורך באימות סטודנט, ואין שום שלב בקורס שדורש תשלום.**

### 6.2 חיבור מאובטח — בחר דרך אחת

גיטהאב **לא מקבל סיסמאות** בפעולות `git push` מאז 2021. יש שתי דרכים תקינות, ומספיקה אחת.
אם אין לך העדפה — בחר במסלול SSH; מגדירים אותו פעם אחת והוא לא מטריד יותר.

#### אפשרות א' — מפתח SSH (מומלץ)

**macOS ו-Windows, אותן פקודות:**

```bash
ssh-keygen -t ed25519 -C "you@example.com"
```

לחץ Enter שלוש פעמים (מיקום ברירת מחדל, ואז סיסמה ריקה פעמיים). עכשיו העתק את המפתח
הציבורי:

```bash
# macOS
pbcopy < ~/.ssh/id_ed25519.pub

# Windows (PowerShell)
Get-Content ~/.ssh/id_ed25519.pub | Set-Clipboard
```

בגיטהאב: לחץ על התמונה שלך בפינה, ואז `Settings > SSH and GPG keys > New SSH key`,
תן שם (`My laptop`), הדבק, ושמור.

בדוק:

```bash
ssh -T git@github.com
```

בפעם הראשונה תישאל `Are you sure you want to continue connecting (yes/no)?` — ענה `yes`.
התשובה הצפויה: `Hi <username>! You've successfully authenticated…`

#### אפשרות ב' — Personal Access Token

1. בגיטהאב: `Settings > Developer settings > Personal access tokens > Tokens (classic)`,
   ואז `Generate new token (classic)`.
2. סמן את ההרשאה **`repo`** בלבד. תוקף: עד סוף הסמסטר.
3. **העתק את הטוקן עכשיו.** גיטהאב לא יציג אותו שוב לעולם.
4. בפעם הראשונה ש-Git יבקש ממך סיסמה — **הדבק את הטוקן במקום הסיסמה.**

כדי שלא יישאל שוב:

```bash
# macOS
git config --global credential.helper osxkeychain

# Windows
git config --global credential.helper manager
```

### 6.3 יצירת המאגר הפרטי שלך

1. פתח את התבנית של הקורס — הקישור בעמוד הקורס במודל.
2. לחץ **`Use this template`** ואז `Create a new repository`.
3. שם המאגר: **`frontend-2027-<תעודת הזהות שלך>`** — בדיוק כך, באנגלית, עם מקפים.
4. **בחר `Private`.** לא `Public`.
5. `Create repository`.

**למה פרטי:** ארבעים מאגרים ציבוריים באותו קורס הם מכונת העתקות.
**למה מהתבנית:** התבנית מביאה איתה את כל ההגדרות — `.vscode`, `.gitattributes`, `.editorconfig`,
והבדיקות האוטומטיות. מאגר ריק שיצרת לבד לא יכיל אותן, וזה יעלה לך נקודות בכל שבוע.

### 6.4 הוסף אותי כמשתף פעולה

1. במאגר שלך: `Settings > Collaborators > Add people`.
2. הקלד את שם המשתמש שלי בגיטהאב — הוא רשום על הלוח ובעמוד הקורס.
3. `Add to repository`. ברשימה תופיע שורה עם הסטטוס `Pending invite`.

**`Pending invite` זה בדיוק מה שאמור להופיע, וזה מספיק.** בגיטהאב מי שמאשר הזמנה הוא
המוזמן, כלומר אני — אתה לא יכול לאשר אותה בעצמך, ולכן אתה גם לא נמדד עליה. אני מאשר את כל
ההזמנות באותו ערב.

**מה כן באחריותך:** שאני אופיע ברשימת ה-`Collaborators`. ודא שאתה רואה אותי שם לפני
שאתה יוצא מהמעבדה — זה מה שנבדק.

**למה זה קריטי:** בשבוע 13 אני טוען את הפרויקט **שלך** למחשבי המבחן לפני שאתה נכנס לחדר.
בלי גישה למאגר אני לא יכול לעשות את זה, **ואין לזה פתרון ביום המבחן**. זו הסיבה שיש על
הסעיף הזה נקודות כבר במטלה הראשונה.

### 6.5 שכפול המאגר, והדחיפה הראשונה

בעמוד המאגר שלך לחץ `Code` והעתק את הכתובת — לשונית `SSH` אם בחרת מפתח, `HTTPS` אם בחרת טוקן.

```bash
cd ~/Documents
git clone git@github.com:YOUR-USERNAME/frontend-2027-123456789.git
cd frontend-2027-123456789
code .
```

עכשיו הדחיפה הראשונה. פתח את `week-01/README.md`, הוסף שורה כלשהי, ושמור:

```bash
git status
git add week-01/README.md
git commit -m "docs: first commit from my machine"
git push
```

**אם `git push` עבר בלי שגיאה — סיימת את החלק הקשה.** רענן את עמוד המאגר בדפדפן וראה את
הקומיט שלך שם.

לא עבר? `git remote -v` יגיד לך על איזה פרוטוקול אתה, ונספח א מכסה את כל הכישלונות הנפוצים
(**א-6** עד **א-9**).

## 7. מאגר החומרים הציבורי, ו-`git pull` שבועי

חומרי הקורס — קבצי הפתיחה, הבריפים והמצגות — יושבים במאגר ציבורי נפרד. שכפל אותו **פעם אחת**,
לתיקייה **אחרת** מזו של המאגר שלך:

```bash
cd ~/Documents
git clone https://github.com/<the account named on the course page>/frontend-2027-materials.git
```

**בכל שבוע, לפני השיעור:**

```bash
cd ~/Documents/frontend-2027-materials
git pull
```

זהו. `git pull` מביא את מה שהתווסף. **אל תערוך קבצים בתוך המאגר הזה** — העתק את מה שאתה
צריך אל המאגר שלך ועבוד שם. אם ערכת בטעות ו-`git pull` מסרב, ראה תקלה **א-9**.

## 8. כלל ההגשה — למד אותו עכשיו, הוא לא ישתנה

> [!submission]
> **בכל מועד הגשה אתה מגיש במודל שני דברים:** כתובת ה-repo, ו-**ה-SHA של הקומיט**.
>
> **ה-SHA מקפיא את ההגשה.** מה שנמצא בקומיט הזה — זה מה שנבדק. דחיפה אחרי המועד לא משנה את
> הציון, ואין על כך ויכוח.

### איך משיגים SHA

**מהטרמינל:**

```bash
git log -1 --format=%H
```

התוצאה היא שורה אחת של 40 תווים, למשל:

```
9f4c1a7e0b2d5836a1c4f7e9d2b8a6c3e5f10947
```

**מגיטהאב:** בעמוד המאגר לחץ על `commits`, ולצד כל קומיט יש כפתור העתקה קטן שמעתיק את
ה-SHA המלא.

### חזרה יבשה — עשה את זה היום

1. ודא שדחפת (`git push`).
2. הרץ `git log -1 --format=%H` והעתק את הפלט.
3. פתח את שאלת ההגשה של שבוע 1 במודל.
4. הדבק את כתובת ה-repo ואת ה-SHA, והגש.

**עשית את זה פעם אחת — ולא תגלה את זה בפעם הראשונה בשבוע 2 בלילה שלפני ההגשה.**
