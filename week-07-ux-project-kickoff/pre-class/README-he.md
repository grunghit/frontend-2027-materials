## מה עושים

1. **העתק את תיקיית הפתיחה.** מהחומרים: את כל התוכן של `week-07-ux-project-kickoff/starter/`
   — כולל `vendor/` ו-`images/` — לתוך `week-07/` במאגר הסמסטר שלך. **את `bad-page.html` לא פותחים
   לעריכה, לא עכשיו ולא אחר כך.**

2. **קרא את מאגר הנושאים פעם אחת** — `project/project-topics-he.md`: ארבע השאלות בראש, ואז 22 הנושאים.
   בחר אחד או שניים שעוברים את ארבע השאלות, וכתוב אותם (מספר ושם) בשורה "נושא מהמאגר / נושא
   עצמאי" בטבלה שבראש `week-07/PROJECT_PLAN.md`. נושא עצמאי מותר — ומאושר בשיעור, לא אחריו.
   ואם יש לך עוד חמש דקות: קרא את `project/project-brief-he.md` מההתחלה עד "מפת אבני הדרך" — כולל המילון "מילים שעוד לא למדת" (API, JSON, CORS, `fetch`). את רשימת הדרישות אפשר לדלג.

3. **קומיט ודחיפה.**

   ```bash
   git add week-07
   git commit -m "week-07: starter and a candidate topic"
   git push
   ```

4. **הוכח שהכול במקום.** מהשורש של מאגר הסמסטר, בטרמינל המשולב של VS Code:

   ```bash
   node <נתיב לחומרים>/week-07-ux-project-kickoff/pre-class/verify.mjs
   ```

   חמש בדיקות, וכולן עוברות: Node · `git` והמאגר · חמשת קובצי הפתיחה ב-`week-07/` · נושא מועמד
   בטבלה · הקומיט האחרון דחוף. אם בדיקה נכשלת — הסקריפט אומר מה, ומה לעשות.

5. **תיקיית תרגול.** העתק את `week-07-ux-project-kickoff/live-code/01-three-green-checks/start/`
   מהחומרים למקום נוח בשם `practice`, ופתח אותה ב-VS Code. יש בה עמוד הסדנאות של הספרייה — שם
   מריצים את הבדיקות במחזור 1. למחזורים 2, 3 ו-5 מעתיקים בכיתה את ה-`start/` של כל אחד.

## אם משהו לא עובד

- `node: command not found` — Node לא מותקן או לא ב-PATH. מדריך ההתקנה של שבוע 1, סעיף 4.
- "חסרים: vendor/tailwind.js" — העתקת את הקבצים ולא את התיקיות. העתק את `vendor/` ו-`images/` כמו שהן.
- "שורת הנושא ריקה" — הכתיבה בתוך הערת ה-`<!-- -->` לא נספרת. מחק את ההערה וכתוב במקומה.
- "קומיטים עדיין לא נדחפו" — `git push`. אם הוא נכשל — `setup/git-panic-he.md` של שבוע 1.

לא צריך. אם משהו כאן לא ברור, שאל את Claude מה הפקודה עושה — **ואז הרץ אותה בעצמך.** את הנושא
בוחרים לבד: בכיתה Claude ימלא לך את התוכנית, ושם תראה למה כדאי שהנושא יהיה שלך קודם.
