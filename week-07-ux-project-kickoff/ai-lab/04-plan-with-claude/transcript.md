# תוכנית פרויקט — PlantPal

## 1. משפט אחד

PlantPal היא פלטפורמה חכמה לניהול צמחי בית, שעוזרת למשתמשים לעקוב אחרי השקיה, דישון ובריאות הצמחים שלהם, לקבל תזכורות בזמן, ולשתף את האוסף עם בני המשפחה.

## 2. למי זה, ומה המסלול המרכזי

**קהל היעד:** חובבי צמחי בית בכל הרמות — ממתחילים שקנו את הצמח הראשון ועד אספנים עם עשרות צמחים, וגם משפחות שמטפלות בצמחים יחד.

**המסלול המרכזי:**

1. המשתמש נרשם ומתחבר עם אימייל וסיסמה (או עם חשבון Google).
2. מוסיף צמח: מצלם אותו, והמערכת מזהה את המין אוטומטית.
3. מגדיר לוח השקיה ודישון, ומקבל תזכורת push כשהגיע הזמן.
4. מסמן "השקיתי", והנתונים מסתנכרנים לשרת ולשאר המכשירים.
5. צופה בדשבורד עם סטטיסטיקות ובהיסטוריית הטיפול בכל צמח.

## 5. ה-API

**Perenual Plant API** — מאגר של יותר מ-10,000 מיני צמחים, עם הנחיות השקיה, אור וטמפרטורה.

```
GET https://perenual.com/api/species-list?key=YOUR_API_KEY&q=monstera
GET https://perenual.com/api/species/details/{id}?key=YOUR_API_KEY
```

צריך להירשם באתר ולקבל מפתח API חינמי (עד 100 בקשות ביום).
לזיהוי צמח מתמונה: **Plant.id API**, וגם הוא דורש מפתח.
ובנוסף **OpenWeatherMap**, כדי להתאים את תדירות ההשקיה למזג האוויר.

> **גם כאן, ולא המכשול הראשי:** שלושה API, ושלושתם דורשים מפתח. נבדק מעמוד שרץ על
> `127.0.0.1`: `fetch('https://perenual.com/api/species-list?q=monstera')` מחזיר **400** ו-
> `{"message":"Missing API Key."}`. מפתח בדף סטטי הוא מפתח שכל מי שפותח DevTools רואה.

# תוכנית פרויקט — Plant Shelf

## 1. משפט אחד

מי שמגדל צמחי בית רואה בעמוד אחד איזה צמח צריך מים היום, מסמן "השקיתי", ושומר לכל צמח תקציר על המין שלו — הכול בדפדפן שלו.

## 2. למי זה, ומה המסלול המרכזי

יואב, 24, סטודנט עם שמונה עציצים בדירה שכורה, שוכח תמיד את הצמח שבחדר השינה. [ניחוש: תיארת רק את עצמך — שיניתי לאדם אחר כדי שיהיה ברור שזו פרסונה. החלף אם אתה המשתמש.]

1. נכנס לעמוד הראשי ורואה למעלה "צריכים מים היום: 2".
2. לוחץ "השקיתי" ליד הפותוס.
3. הפותוס יורד לרשימת "בסדר", עם תאריך ההשקיה הבאה.
4. מוסיף צמח חדש: שם, מין, מיקום, כל כמה ימים.
5. פותח את עמוד הצמח וקורא את התקציר על המין.

## 3. האוסף

**הישות:** צמח (`Plant`). אחת.

| שדה | טיפוס | מאיפה הוא בא | מוצג? מסונן לפיו? |
|---|---|---|---|
| `id` | `string` | `crypto.randomUUID()` בעת ההוספה | לא מוצג. ב-URL של עמוד הצמח |
| `name` | `string` | המשתמש | מוצג, ממוין |
| `species` | `string \| null` | המשתמש. `null` כשלא ידוע | מוצג. משמש לחיפוש התקציר |
| `room` | `string` | המשתמש, מרשימה סגורה [ניחוש: הרשימה — סלון, מטבח, חדר שינה, מרפסת] | מוצג, מסונן לפיו |
| `waterEveryDays` | `number` | המשתמש, 1–30 | משמש לחישוב "צריך מים" |
| `lastWatered` | `string \| null` | תאריך ISO. `null` = עוד לא הושקה מאז שנוסף | מוצג כ"לפני N ימים" |
| `note` | `string` | המשתמש, יכול להיות ריק | מוצג בעמוד הצמח |
| `addedAt` | `string` | `new Date().toISOString()` | ממוין לפיו |

"צריך מים היום" **אינו שדה** — הוא נגזר מ-`lastWatered` ו-`waterEveryDays`.

1. הוספה, עריכה ומחיקה של צמח, עם שמירה ב-`localStorage`.
2. "צריכים מים היום", נגזר, בראש המדף.
3. "השקיתי" — מעדכן את `lastWatered`.
4. סינון לפי חדר ומיון לפי שם או לפי "הכי צמא".
5. התקציר על המין מוויקיפדיה, עם ארבעת המצבים.

**אם יישאר זמן:**

- ביטול (undo) אחרי מחיקה.
- ייצוא המדף לקובץ JSON.

**לא אבנה, במפורש:**

- התחברות או משתמשים. אין שרת, והמדף של אדם אחד.
- תזכורות push. דורשות service worker ושרת, ואינן בבריף.
- זיהוי צמח מתמונה. כל API כזה דורש מפתח.
- שיתוף המדף עם אחרים. זה משתמש שני, כלומר ישות שנייה.
