this week one source

The button is defined once, on components.html, and every use is a copy of that — by hand, no build step. That is what CA5 asks for. On this page the six are generated from one string, so that the demo has a single source too; the discipline is the same and the audit cannot tell them apart, which is the point. 

components.html — the ONE definition:

  <!-- button / primary -->
  <button class="cursor-pointer rounded-lg
    bg-brand-500 px-5 py-2 text-sm font-semibold
    text-white hover:bg-brand-700">Label</button>

everywhere else: copy that line.
changed your mind? change it there, then re-copy.

week 9 one function

Read this one; do not write it yet. It needs template literals and functions, which is week 7, and the render pattern it belongs to is week 9. It is here so you know the ladder has a top. 

const BUTTON =
  'cursor-pointer rounded-lg bg-brand-500 ' +
  'px-5 py-2 text-sm font-semibold text-white ' +
  'hover:bg-brand-700';

const button = (label) =>
  `<button type="button" class="${BUTTON}">${label}</button>`;

LABELS.map(button).join('')

Notice what is not on this ladder. @apply is not a rung. It looks like the obvious answer and it is demo 10, on its own, because what it actually does is walk you back down to demo 01.

And notice what the ladder is really about. Not tidiness — a SINGLE SOURCE. Six copies of anything drift, in any language, in any framework. The rungs differ only in how hard the language makes it to have one copy.
