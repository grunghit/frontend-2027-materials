## א. "העמוד ריק / לבן לגמרי"

**רמז.** הדפדפן לא שבר כלום. הוא בדיוק עשה מה שביקשת — וביקשת מעט.

**אסטרטגיה.** בדוק שני דברים לפי הסדר: (1) האם אתה בכלל מסתכל על הקובץ הנכון? הסתכל בשורת
הכתובת. (2) האם כתבת משהו **בתוך** `body`? כל מה שנמצא ב-`head` לא מוצג.

**כמעט-פתרון.** תוכן מוצג רק בין `<body>` ל-`</body>`. אם הקובץ שקיבלת נראה כמו הערות בלבד,
זה נכון — הן מסמנות לך איפה לכתוב:

```html
<body>
  <header>
    <h1>Your name</h1>
  </header>
</body>
```

## ב. "התמונה לא מופיעה"

**רמז.** פתח את כלי הפיתוח, לשונית `Network`, ורענן. יש שם שורה אדומה עם 404?

**אסטרטגיה.** הנתיב נספר **מהקובץ שבו הוא כתוב**, לא משורת הכתובת ולא מהתיקייה שפתחת ב-VS Code.
אם `index.html` ו-`images/` יושבים באותה תיקייה, הנתיב מתחיל ב-`images/` — בלי לוכסן בהתחלה.

**כמעט-פתרון.**

```html
<!-- index.html and images/ sit in the same folder -->
<img src="images/placeholder.svg" alt="…" width="240" height="240" />

<!-- three ways to get it wrong: -->
<!-- <img src="/images/placeholder.svg">                    from the server root -->
<!-- <img src="C:\Users\me\Desktop\images\placeholder.svg"> a Windows path -->
<!-- <img src="file:///Users/me/Desktop/images/x.svg">      an absolute local path -->
```

שלוש האחרונות עולות לך נקודות, גם אם התמונה מופיעה **אצלך**.

## ג. "לחיצה על התווית לא עושה כלום"

**רמז.** התווית לא יודעת לאיזה שדה היא שייכת. משהו חייב לחבר ביניהם.

**אסטרטגיה.** החיבור הוא `for` על התווית שמצביע על `id` של השדה. שים לב: על ה-`id`,
**לא** על ה-`name`. זו הטעות הכי שקטה בסעיף הזה — הכול נראה נכון והכלום לא עובד.

**כמעט-פתרון.**

```html
<label for="email">Your email</label>
<input type="email" id="email" name="email" required />
```

`id` הוא לדף (התווית מצביעה עליו). `name` הוא לשרת (זה מה שנשלח). שניהם נחוצים, והם לא
חייבים להיות זהים — אבל נוח שכן.

## ד. "הוולידטור נותן לי שבע שגיאות ואני לא מבין מה קורה"

**רמז.** ספור כמה מהן מדברות על תג סוגר. כנראה יש לך טעות אחת, לא שבע.

**אסטרטגיה.** תקן את **השורה הראשונה בפלט** בלבד, ואז הרץ שוב. תג שנפתח ולא נסגר משאיר את
המחסנית של הדפדפן פתוחה, וכל תג סוגר אחריו מדווח שגיאה משלו. תיקון אחד מוחק את כולן.

**כמעט-פתרון.** שלוש השגיאות שכמעט כולם מקבלים השבוע:

| ההודעה | מה זה אומר |
|---|---|
| `Unclosed element '<section>'` | פתחת `section` וסגרת אותו במשהו אחר, בדרך כלל `</div>` |
| `Duplicate ID "x"` | אותו `id` על שני אלמנטים. `id` הוא ייחודי במסמך |
| `<img> is missing required "alt" attribute` | בדיוק מה שכתוב |

## ה. "אני לא מצליח לדחוף / GitHub מבקש סיסמה"

**רמז.** אם אתה נשאל על סיסמה — אתה עובד ב-HTTPS, ו-GitHub כבר לא מקבל סיסמאות שם.

**אסטרטגיה.** שתי דרכים תקינות, ומספיק אחת: מפתח SSH, או credential helper עם Personal Access
Token. שתיהן מוסברות צעד-אחר-צעד בפרק 6 של מדריך ההתקנה, בשני מסלולים נפרדים ל-macOS ול-Windows.

**כמעט-פתרון.** בדוק קודם על איזה פרוטוקול אתה בכלל:

```bash
git remote -v
```

`https://github.com/...` — צריך token או helper. `git@github.com:...` — צריך מפתח SSH.
אם השגיאה היא `remote: Repository not found.` והמאגר קיים — אתה מחובר לחשבון הלא נכון.

## ו. "מה בכלל השוני בין section, article ו-div?"

**רמז.** אל תשאל איך זה נראה. שאל מה זה **אומר**.

**אסטרטגיה.** שלוש שאלות, בסדר הזה:

1. אם אשלח את הקטע הזה לבד בהודעה — הוא עדיין הגיוני? אם כן, זה `article`.
2. יש לו כותרת משלו והוא חלק תמטי מהעמוד? זה `section`.
3. אני צריך את זה רק כדי לתלות עליו עיצוב? זה `div`, וזה בסדר גמור.

**כמעט-פתרון.** במטלה הזו, המבנה הסביר הוא:

```html
<main>
  <section id="about">
    <h2>About me</h2>
    <!-- text, image -->
    <aside><!-- a side note that is not the main point --></aside>
  </section>

  <section id="contact">
    <h2>Contact me</h2>
    <!-- the form -->
  </section>
</main>
```

`section` בלי כותרת הוא כמעט תמיד `div` במסווה.

## ז. "עשיתי הכול ועדיין יש גלילה אופקית ב-375"

**רמז.** משהו אחד בעמוד רחב מהמסך. כמעט תמיד זה אותו דבר.

**אסטרטגיה.** צר את חלון הדפדפן עד שהגלילה מופיעה, ואז ב-`Elements` עבור על האלמנטים
ותראה איזה מהם חורג. שני החשודים: תמונה בלי `width`/`height`, או מחרוזת ארוכה בלי רווחים —
כתובת URL, מייל ארוך, או שם קובץ.

**כמעט-פתרון.** אסור CSS השבוע, ולכן הפתרון הוא בתוכן עצמו: תן לתמונה `width` ו-`height`
במידה סבירה (240 מספיק), ואל תשתול בטקסט מחרוזת ארוכה בלי רווחים. אם אתה חייב להציג כתובת
ארוכה — הפוך אותה לקישור עם טקסט קצר:

```html
<a href="https://a.very.long.example.com/path">View the source</a>
```

## ח. "סיימתי את הליבה. מה עכשיו?"

**רמז.** אל תלך לקישוטים. אין CSS השבוע, וזה בכוונה.

**אסטרטגיה.** לך לפי הסדר בבריף: קודם `time`
ו-`article`/`aside`, אחר כך העמוד השני. העמוד השני הוא הסעיף שמלמד הכי הרבה, כי הוא מכריח
אותך לכתוב נתיבים יחסיים לשני הכיוונים.

**כמעט-פתרון.** קישור דילוג, מהשכבה השלישית, הוא שלוש שורות ושווה 3 נקודות:

```html
<body>
  <a href="#main">Skip to content</a>
  <!-- header, nav -->
  <main id="main" tabindex="-1">…</main>
</body>
```

`tabindex="-1"` הוא מה שמאפשר לפוקוס לנחות על `main` אחרי הקפיצה, בלי להכניס אותו לסדר ה-Tab.
