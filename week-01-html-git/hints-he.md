## א. "העמוד ריק / לבן לגמרי", או "הטאב מציג index.html במקום השם שלי"

**רמז.** הדפדפן לא שבר כלום. הוא בדיוק עשה מה שביקשת — וביקשת מעט. ומה-`head` רואים על המסך
דבר אחד בלבד: את ה-`title`, בטאב.

**אסטרטגיה.** בדוק שלושה דברים לפי הסדר: (1) האם אתה בכלל מסתכל על הקובץ הנכון? הסתכל בשורת
הכתובת — `http://127.0.0.1:5500`, לא `file://`. (2) האם כתבת משהו **בתוך** `body`? כל מה שנמצא
ב-`head` לא מוצג. (3) האם ה-`title` בתוך ה-`head`? `title` בתוך ה-`body` לא מוצג בעמוד ולא תמיד
מגיע לטאב — והוולידטור מתלונן עליו.

**כמעט-פתרון.** תוכן מוצג רק בין `<body>` ל-`</body>`. אם הקובץ שקיבלת נראה כמו הערות בלבד,
זה נכון — הן מסמנות לך איפה לכתוב:

```html
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <title>Your name</title>
</head>
<body>
  <header>
    <h1>Your name</h1>
  </header>
</body>
```

## ב. "הפסקה שלי ענקית ומודגשת"

**רמז.** היא לא פסקה. היא חלק מהכותרת — כי הכותרת לא נסגרה.

**אסטרטגיה.** פתח DevTools, Elements, ותסתכל **מי הילד של מי**. אם ה-`p` יושב בתוך ה-`h1`,
הדפדפן סגר את מה שאתה שכחת — במקום אחר ממה שהתכוונת. הוולידטור אומר את זה במילים:
`Unclosed element '<h1>'`.

**כמעט-פתרון.** סוגרים בסדר הפוך לפתיחה. `h1` נפתח — `h1` נסגר — ורק אז `p`:

```html
<h1>Your name</h1>
<p>One line about you.</p>
```

## ג. "הוולידטור נותן לי שבע שגיאות ואני לא מבין מה קורה"

**רמז.** ספור כמה מהן מדברות על תג סוגר. כנראה יש לך טעות אחת, לא שבע.

**אסטרטגיה.** תקן את **השורה הראשונה בפלט** בלבד, ואז הרץ שוב. תג שנפתח ולא נסגר משאיר את
המחסנית של הדפדפן פתוחה, וכל תג סוגר אחריו מדווח שגיאה משלו. תיקון אחד מוחק רבות.

**כמעט-פתרון.** שלוש השגיאות שכמעט כולם מקבלים השבוע:

| ההודעה | מה זה אומר |
|---|---|
| `Unclosed element '<section>'` | פתחת `section` וסגרת אותו במשהו אחר, בדרך כלל `</div>` |
| `Duplicate ID "x"` | אותו `id` על שני אלמנטים. `id` הוא ייחודי במסמך |
| `<p> element is not permitted as content under <ul>` | לתוך `ul` נכנס רק `li`. כל דבר אחר — בתוך ה-`li` |

## ד. "הניווט שלי לא נתפס בבדיקה"

**רמז.** הוולידטור ירוק, וזה לא אומר שזו רשימה. קורא מסך סופר `li`, לא `a`.

**אסטרטגיה.** ב-DevTools, Elements, לשונית Accessibility: בתוך `navigation` צריך להופיע
`list` ובתוכו `listitem`-ים. אם יש שם רק `link`, `link` — אין רשימה. וגם: `nav` הוא לניווט
ראשי; `main` יש בדיוק אחד; `div class="header"` הוא לא `header`.

**כמעט-פתרון.** ארבע רמות, בדיוק בסדר הזה — `nav > ul > li > a`:

```html
<nav aria-label="Main">
  <ul>
    <li><a href="#about">About me</a></li>
    <li><a href="#contact">Contact me</a></li>
  </ul>
</nav>
```

## ה. "התמונה לא מופיעה"

**רמז.** פתח את כלי הפיתוח, לשונית `Network`, ורענן. יש שם שורה אדומה? ובקונסול — איזו משלוש
ההודעות מופיעה?

**אסטרטגיה.** הנתיב נספר **מהקובץ שבו הוא כתוב**, לא משורת הכתובת ולא מהתיקייה שפתחת ב-VS Code.
אם `index.html` ו-`images/` יושבים באותה תיקייה, הנתיב מתחיל ב-`images/` — בלי לוכסן בהתחלה.
ושים לב לאותיות: `Images/` ו-`images/` הם אותה תיקייה ב-macOS ושתי תיקיות שונות בשרת שלי.

**כמעט-פתרון.**

```html
<!-- index.html and images/ sit in the same folder -->
<img src="images/placeholder.svg" alt="…" width="240" height="240" />

<!-- three ways to get it wrong, and what the console says for each: -->
<!-- <img src="/images/placeholder.svg">                    404 — from the server root -->
<!-- <img src="C:\Users\me\Desktop\images\placeholder.svg"> ERR_UNKNOWN_URL_SCHEME -->
<!-- <img src="file:///Users/me/Desktop/images/x.svg">      Not allowed to load local resource -->
```

שתי האחרונות (`C:\` ו-`file:`) עולות לך נקודות, גם אם התמונה מופיעה **אצלך** — הן עובדות רק
על המחשב שלך. הראשונה, עם לוכסן בהתחלה, לא מורידה נקודות: הבדיקה מריצה את תיקיית השבוע כשורש
השרת. אבל ב-Live Server שלך השורש הוא המאגר כולו, התמונה לא נטענת, והעמוד שבור — תקן גם אותה.

## ו. "מה כותבים ב-alt"

**רמז.** מה שהיית אומר בטלפון למי שלא רואה את המסך. לא את שם הקובץ, לא "image".

**אסטרטגיה.** שתי החלטות בלבד: התמונה נושאת מידע — תאר מה רואים בה, במשפט. התמונה קישוט —
`alt=""`, במפורש, ריק. `alt` חסר הוא לא החלטה: קורא המסך יקריא את שם הקובץ.

**כמעט-פתרון.**

```html
<img src="images/portrait.svg" alt="Illustrated portrait of Maya wearing round glasses" width="240" height="240" />
<img src="images/divider.svg" alt="" width="120" height="12" />
```

## ז. "עשיתי הכול ועדיין יש גלילה אופקית ב-375"

**רמז.** משהו אחד בעמוד רחב מהמסך. כמעט תמיד זו תמונה ברוחב הטבעי שלה.

**אסטרטגיה.** פתח את סרגל המכשירים ב-DevTools, בחר 375, ותראה את פס הגלילה. הדבק בקונסול:

```js
[...document.querySelectorAll('*')].filter((el) => el.getBoundingClientRect().right > 376);
```

מה שחוזר הוא מה שחורג. שני החשודים: תמונה בלי `width`/`height` שנכנסים, או מחרוזת ארוכה בלי
רווחים — כתובת URL, מייל ארוך, שם קובץ.

**כמעט-פתרון.** אסור CSS השבוע, ולכן הפתרון הוא בתוכן עצמו: תן לתמונה `width` ו-`height`
שנכנסים ב-375, **באותו יחס** כמו התמונה (תמונה של 1200 על 675 מקבלת 320 על 180). בשבוע ה-CSS
`max-width: 100%` יעשה את זה נכון בכל רוחב. ואם אתה חייב להציג כתובת ארוכה — הפוך אותה לקישור
עם טקסט קצר:

```html
<a href="https://a.very.long.example.com/path">View the source</a>
```

## ח. "העמוד השני לא נמצא / אין דרך חזרה"

**רמז.** עמוד שני מקושר בדיוק כמו תמונה: הנתיב נספר מהקובץ, ולוכסן בהתחלה הוא 404.

**אסטרטגיה.** `about.html` יושב **ליד** `index.html`, באותה תיקייה. מ-`index.html` הקישור הוא
`about.html`; מ-`about.html` הקישור חזרה הוא `index.html`. שניהם בלי `/` בהתחלה. הבדיקה פותחת
את הקובץ שהקישור מצביע עליו ומחפשת בו קישור שמכיל `index.html`.

**כמעט-פתרון.**

```html
<!-- in index.html -->
<li><a href="about.html">Longer version</a></li>

<!-- in about.html -->
<p><a href="index.html">Back to the home page</a></p>
```

## ט. "מה בכלל השוני בין section, article, aside ו-div?"

**רמז.** אל תשאל איך זה נראה. שאל מה זה **אומר**.

**אסטרטגיה.** ארבע שאלות, בסדר הזה:

1. אם אשלח את הקטע הזה לבד בהודעה — הוא עדיין הגיוני? אם כן, זה `article`.
2. הוא קשור לעמוד רק בעקיפין — טריוויה, הערת צד? זה `aside`.
3. יש לו כותרת משלו והוא חלק תמטי מהעמוד? זה `section`.
4. אני צריך את זה רק כדי לתלות עליו עיצוב? זה `div`, וזה בסדר גמור.

ואם שאלת את Claude — בדוק את התשובה ב-MDN לפני שאתה מקליד. ראית היום למה.

**כמעט-פתרון.** במטלה הזו, המבנה הסביר הוא:

```html
<main>
  <section id="about">
    <h2>About me</h2>
    <!-- text, image -->
    <aside><!-- a side note that is not the main point --></aside>
  </section>

  <section id="learning">
    <h2>What I am learning</h2>
    <article><!-- one reading note that stands on its own --></article>
  </section>
</main>
```

`section` בלי כותרת הוא כמעט תמיד `div` במסווה.

## י. "אני משתמש ב-b ו-i, ומה רע ב-br"

**רמז.** הפיקסלים זהים. ההבדל הוא למי שלא רואה את המסך.

**אסטרטגיה.** `strong` אומר "חשוב", `em` אומר "ההדגשה משנה את המשפט". `b` ו-`i` לא אומרים
כלום — הם לא פסולים ולא מיושנים, אבל השבוע הם עולים נקודות כי ברירת המחדל שלך צריכה להיות
משמעות. ו-`br` הוא שבירת שורה שהיא חלק מהתוכן (כתובת, שיר) — לא ריווח. שתי פסקאות הן שני
`p`.

**כמעט-פתרון.**

```html
<p>Deadline: <strong>Sunday</strong>. <em>Do not</em> be late.</p>
<p>A second paragraph is a second p, not two br tags.</p>
```

## יא. "הקישור החוצה — מה חסר בו"

**רמז.** `target="_blank"` נותן לטאב החדש הפניה חזרה לעמוד שלך.

**אסטרטגיה.** קישור לאתר אחר הוא כתובת מלאה, `https://` ועד הסוף. אם הוא נפתח בטאב חדש,
הוא נושא `rel="noopener noreferrer"` — `noopener`, מילה אחת. הבדיקה בודקת שיש לפחות קישור
`https://` אחד, ושכל `target="_blank"` בעמוד נושא את שתי המילים.

**כמעט-פתרון.**

```html
<a href="https://developer.mozilla.org/" target="_blank" rel="noopener noreferrer">MDN</a>
```

## יב. "git add . סחף לי קובץ", או "אני לא מצליח לדחוף / GitHub מבקש סיסמה"

**רמז.** `git status` לפני `git add`, ו-`git status` אחרי. תמיד. ואם אתה נשאל על סיסמה —
אתה עובד ב-HTTPS, ו-GitHub כבר לא מקבל סיסמאות שם.

**אסטרטגיה.** קובץ שנכנס לאזור ההכנה בטעות יוצא ממנו בפקודה אחת, לפני הקומיט. ולדחיפה שתי
דרכים תקינות, ומספיק אחת: מפתח SSH, או credential helper עם Personal Access Token. שתיהן
מוסברות צעד-אחר-צעד בפרק 6 של מדריך ההתקנה, ו-`git-panic-he.md` מכסה את חמשת המצבים
שבאמת קורים.

**כמעט-פתרון.**

```bash
git restore --staged week-01/index-old.html   # out of the staging area
rm week-01/index-old.html                     # and out of the folder

git remote -v                                 # which protocol am I on?
```

`https://github.com/...` — צריך token או helper. `git@github.com:...` — צריך מפתח SSH.
אם השגיאה היא `remote: Repository not found.` והמאגר קיים — אתה מחובר לחשבון הלא נכון.
