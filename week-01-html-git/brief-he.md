> [!goal]
> לבנות את העמוד הראשון של האתר האישי שלך — סמנטי, נגיש, עם טופס, שעובר ולידציה נקייה —
> ולדחוף אותו למאגר הפרטי שלך בגיטהאב עם היסטוריה שאפשר לקרוא.

זו לא מטלת תרגול שנזרקת בסוף השבוע. **העמוד הזה הוא נקודת הפתיחה של שבוע 2**, ומשם הוא ממשיך
איתך עד סוף הסמסטר. כל מה שתבנה כאן תסדר בשבוע הבא ב-CSS, ולכן שווה לבנות אותו נכון עכשיו.

חצי מהמטלה הזו היא לא HTML. היא **התשתית**: המאגר, ההרשאה, הקומיטים והחזרה היבשה על ההגשה.
זה נראה כמו טכני-מנהלי, וזה לא — סטודנט שמגיע לשבוע 7 עם סביבה שבורה מפסיד שבוע שלם, וסטודנט
שלא שלח לי הזמנה כמשתף פעולה לא יוכל לגשת למבחן על הפרויקט שלו בשבוע 13.

## תוצרי למידה

בסיום המטלה תדע:

1. לכתוב מסמך HTML שלם מאפס — כולל `<!doctype html>`, `lang`, `charset` ו-`viewport` — ולהסביר מה כל אחד מהם עושה.
2. לבחור אלמנט לפי **מה שהוא אומר** ולא לפי איך שהוא נראה: `header`, `nav`, `main`, `section`, `article`, `aside`, `footer`.
3. לבנות טופס נגיש עם `fieldset`, `legend`, ו-`label` מקושר לכל שדה.
4. לכתוב נתיבים יחסיים שעובדים גם על מחשב אחר.
5. להריץ ולידטור, לקרוא את הפלט שלו, ולתקן לפי הסדר.
6. לנהל מאגר Git מהטרמינל: `init` / `add` / `commit` / `push`, ולהוציא ממנו SHA.

## לפני שמתחילים — סביבת העבודה

אם משהו במדריך ההתקנה עדיין לא ירוק אצלך, **עצור ותסגור את זה עכשיו**, לפני שאתה כותב שורת HTML
אחת. המדריך נמצא ב-`setup/setup-he.pdf`, ונספח התקלות בסופו מכסה את השגיאות שבאמת קורות.
אני בכיתה עכשיו. בשבוע 7 לא אהיה זמין באותה מידה.

> [!note] הכלל הכי חשוב מהשבוע הראשון
> **עמוד נפתח תמיד דרך Live Server. אף פעם לא בלחיצה כפולה על הקובץ.**
> לחיצה כפולה פותחת אותו בכתובת `file://`, וזה שובר את `fetch` (שבוע 11), מודולים של ES (שבוע 7)
> ו-`localStorage` (שבוע 10). ההרגל שנוצר בשבוע 1 מתפוצץ בשבוע 10.

> [!note] ואם JavaScript חלודה אצלך
> בשבוע 7 אנחנו מתחילים לכתוב JavaScript, וההרצאה **לא** תלמד משתנים, לולאות ותנאים —
> אתם כבר מתכנתים, וזה יבזבז לכם את השעה. מי שרוצה לרענן תחביר לפני כן ימצא את הכול
> ב-`week-07/primer/` שבמאגר החומרים: רענון קצר ותשעה תרגילים עם פתרונות שרצים על העמוד.
> **אופציונלי, לא נבדק, לא נבחן.** אני מזכיר את זה עכשיו ולא בשבוע 7 כדי שיהיה זמן.

## המשימה, שלב אחר שלב

1. **צור את המאגר הפרטי שלך** {core}
   מתבנית הקורס, בשם `frontend-2027-<תעודת הזהות שלך>`, **פרטי**. פעם אחת, לכל הסמסטר.
   למה פרטי: ארבעים מאגרים ציבוריים באותו קורס הם מכונת העתקות.

2. **הוסף אותי כמשתף פעולה** {core}
   `Settings > Collaborators > Add people`, והוסף את שם המשתמש שנתתי בכיתה.
   **ברגע שאתה רואה אותי ברשימה — סיימת את הסעיף, גם אם כתוב לידי `Pending invite`.**
   האישור הוא בצד שלי ואני עושה אותו באותו ערב; אתה לא מאבד נקודות על משהו שאינו בידיך.
   בלי הגישה הזו לא אוכל לטעון את הפרויקט שלך למחשבי המבחן בשבוע 13, ואין לזה פתרון ביום המבחן.

3. **שכפל את המאגר למחשב שלך והעתק אליו את קבצי הפתיחה** {core}
   `git clone`, ואז העתק את תוכן תיקיית ה-`starter` לתוך `week-01/`. פתח את התיקייה ב-VS Code
   והרץ דרך Live Server.

4. **בנה את שלד המסמך** {core}
   `<!doctype html>`, `<html lang>`, `<meta charset>`, `<meta name="viewport">`, ו-`<title>` אמיתי
   שמתאר את העמוד. הכותרת שקיבלת היא `CHANGE ME` — היא לא תעבור בדיקה.

5. **בנה את מבנה העמוד** {core}
   `header` עם `h1` יחיד ושורה עליך · `nav` עם `ul` של קישורים לאזורי העמוד · `main` אחד ויחיד ·
   `footer`. בתוך `main` לפחות שני `section` עם `id` ועם `h2`.
   `h1` הוא רמה בתוכן העניינים, לא גודל טקסט.

6. **כתוב תוכן אמיתי, עם תמונה** {core}
   שתי פסקאות עליך לפחות, ותמונה אחת עם `alt` שמתאר מה רואים בה — לא שם הקובץ.
   יש תמונה מוכנה ב-`images/placeholder.svg`; החלף אותה בשלך אם בא לך. תן לכל `img` גם
   `width` וגם `height`.

7. **בנה טופס יצירת קשר** {core}
   בתוך `section` משלו: `form > fieldset > legend`, ולפחות **ארבעה שדות**, לכל אחד
   `label` עם `for` שמצביע על ה-`id` של השדה. לפחות שדה אחד `required`, וכפתור שליחה.
   בחר `type` הגיוני לכל שדה. אין שרת השבוע — לחיצה על שליחה לא תשלח כלום, וזה תקין.

8. **הרץ ולידטור עד שהוא נקי** {core}
   מהטרמינל המשולב, בתוך תיקיית העמוד:

   ```bash
   npx html-validate index.html
   ```

   תקן את **השגיאה הראשונה** והרץ שוב. שלוש שגיאות מייצרות לפעמים שבע שורות פלט; אחרי תיקון
   הראשונה רובן נעלמות. בסוף — מחק כל סימון `CODE HERE` שנשאר בקובץ.

9. **עשה לפחות שלושה קומיטים משמעותיים ודחוף** {core}
   קומיט אחרי כל שלב, לא קומיט ענק אחד בסוף. הודעה שאפשר להבין בלי לפתוח את השינוי:

   ```bash
   git add index.html
   git commit -m "feat: add semantic page skeleton"
   git push
   ```

10. **הגש במודל — חזרה יבשה על ההגשה** {core}
    כתובת ה-repo, וגם ה-SHA של הקומיט האחרון:

    ```bash
    git log -1 --format=%H
    ```

11. **הרחב את העמוד** {stretch}
    `article` או `aside` בשימוש נכון · תאריך ב-`time` עם `datetime` · **עמוד שני**
    (`about.html`) המקושר בנתיב יחסי, שמקשר חזרה — ומשם חזרה ל-`index.html`.
    ודא שאין גלילה אופקית ברוחב 375, ושאפשר לעבור על כל העמוד ב-Tab.

12. **סגור את הפינות** {challenge}
    קישור דילוג בראש העמוד שמוביל אל `main` · `details`/`summary` או `picture` עם `srcset` ·
    אפס ליקויי נגישות חמורים ב-axe.

> [!constraints]
> - **אסור לכתוב CSS השבוע.** לא קובץ חיצוני, לא `<style>`, ולא `style=""`. העמוד אמור להיראות
>   פשוט. שבוע 2 הוא זה שמסדר אותו, ועל אותו קובץ בדיוק.
> - **אסור JavaScript.** אין השבוע שום דבר שדורש אותו.
> - **אסור להעלות קבצים דרך ממשק הדפדפן של GitHub.** רק `git add` / `git commit` / `git push`
>   מהטרמינל. מהשבוע הבא מותר גם הפאנל הגרפי של VS Code.
> - **אסור נתיב מוחלט מקומי.** `file:///Users/...` או `C:\Users\...` בתוך `src` או `href` הם
>   פסילה של הסעיף — הם עובדים רק על המחשב שלך.
> - אסור `node_modules` או קבצים זמניים במאגר.

## בדיקה עצמית

- העמוד נפתח דרך Live Server בכתובת `http://127.0.0.1:5500`, ואין שגיאות בקונסול.

- אין בקובץ אף סימון `CODE HERE`.
- לחיצה על **המילים** של כל תווית בטופס מקפיצה את הסמן לשדה שלה.
