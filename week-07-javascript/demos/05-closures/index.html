The loop everybody has seen, and the pattern you are about to ship

1 — three functions, one variable

for (var i = 0; i < 3; i++) {
  jobs.push(() => i);
}
jobs.map((j) => j());

 

The functions are fine. They all close over the same i, and by the time any of them runs, the loop has finished and that one i is 3.

2 — three functions, three variables

for (let i = 0; i < 3; i++) {
  jobs.push(() => i);
}
jobs.map((j) => j());

 

One keyword. let creates a fresh binding per iteration, so each function closes over a different one. Nothing about the functions changed.

3 — the reason anyone cares

function createStore() {
  let state = { count: 0 };
  const listeners = new Set();
  return {
    getState: () => state,
    setState(patch) { … },
    subscribe(fn) { … },
  };
}

 

state is a plain let inside a function that has already returned. Nothing on this page can name it. That is the same closure as panel 1 — and here it is the reason your state cannot be corrupted from outside its file.
